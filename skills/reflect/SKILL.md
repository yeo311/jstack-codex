# 작업에서 배우기

1. 활성 작업의 판단·실행·결과만 읽어 반복 오류와 도움이 된 방법을 찾는다.
2. 같은 Codex 모델의 내부 read-only readers가 구현·검증·소통 관점을 나눌 수 있다. 고정 세 명이나 다른 모델 호출은 요구하지 않는다.
3. 교훈마다 실제 근거, 반복 가능성, 적용 범위를 적고 generic 원칙·project convention·개인 선호를 구분한다.
4. 구조·자료형·기존 검사 개선을 먼저 제안한다. 개인 스킬 또는 설치된 plugin을 수정하는 권한은 별도 확인하고 memories를 자동 변경하지 않는다.

## 공통 경계

[개인 상태](../jstack-mode/references/state.md)와 [프런트엔드](../jstack-mode/references/frontend.md), [권한](../jstack-mode/references/permissions.md)을 따른다. 분업이 필요할 때만 [일반 Codex 병렬 기준](../jstack-mode/references/parallel.md)을 읽는다. 설명은 [한국어 문체](../jstack-mode/references/writing.md)를 따른다.

## 결과

반복 교훈·실제 근거·적용 범위·구조적 개선 제안·승인된 개인 스킬 수정과 수정하지 않은 항목.
